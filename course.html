Проблема: один и тот же код, разные вселенные

Тот же код. Те же данные. Та же логика.
Бэктест: +287%. Live: −28%.
Разница — не рынок. Разница — пять механизмов которые бэктест игнорирует.

Главное правило: Если система не воспроизводит transaction costs, slippage и bar-close latency — она не тестирует реальность. Она тестирует оптимизм.

Механизм #1 — Bar-Close Bias

Бот читал цену незакрытой свечи. В тесте это работает. В реальности — нет.

❌ Как было (утечка)
signal = df.iloc[i]["close"]
# Читаем цену i-й свечи
# Которая ещё не закрылась
# Бот "видит будущее"
✅ Как надо (честно)
signal = df.iloc[i-1]["close"]
# Читаем цену ЗАКРЫТОЙ свечи
# Вход на open следующей
# Никакого lookahead

Механизм #2 — Transaction Costs

$500 депозит. 159 сделок в день (до оптимизации). Считаем:

true_cost_analysis.py 
def true_cost_analysis(trades_per_day, avg_size_usdt, fee_rate=0.0004):
    # Binance Futures maker/taker: 0.02%/0.04% → avg ~0.04%
    daily_volume  = trades_per_day * avg_size_usdt * 2  # вход + выход
    daily_fees    = daily_volume * fee_rate
    monthly_fees  = daily_fees * 30
    annual_fees   = monthly_fees * 12

    return {
        "daily_fees":   daily_fees,
        "monthly_fees": monthly_fees,
        "annual_pct":  annual_fees / 500 * 100,  # % от депозита
    }

# До оптимизации: 159 сделок/день по $22
result = true_cost_analysis(159, 22)
# monthly_fees: $124 → 24.9% годовых только на комиссиях

Наши инструменты: честный vs быстрый

В системе два бэктест-инструмента с принципиально разной точностью:

сравнение инструментов 
# ── v13_backtest.py ────────────────────────────────────
# Скорость: ~3 секунды
# Метод:    proxy-scores (аппроксимация)
# Честность: говорит "LIKELY" — признаёт неточность
# Когда:    быстрая проверка гипотезы

# ── historical_replay_validator.py ─────────────────────
# Скорость: ~3 минуты (реальные OHLCV с Binance)
# Метод:    tick-level replay, реальные цены
# Честность: включает costs, slippage, bar-close
# Когда:    перед деплоем изменений
Правило системы: v13_backtest для ежедневной проверки. historical_replay перед каждым деплоем изменений в confluence логику.
